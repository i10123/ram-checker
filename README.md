# RAM Diagnostic Suite

Windows-приложение на C# / WPF (.NET 10) для просмотра характеристик модулей, мониторинга памяти и базовой диагностики буфера процесса. Интерфейс основан на согласованном макете Figma.

## Запуск

Нужен Windows и .NET 10 Desktop Runtime; для сборки — .NET 10 SDK.

```powershell
dotnet run --project RAMChecker/RAMChecker.csproj -c Release
```

Или откройте `RAMChecker/RAMChecker.slnx` в Visual Studio. После сборки исполняемый файл находится в `RAMChecker/bin/Release/net10.0-windows/RAMChecker.exe`.

Для текущих таймингов и датчиков откройте «Обзор» → **«Запустить от администратора»** и подтвердите запрос Windows. Откроется новое окно на разделе «Обзор». При отмене UAC приложение продолжит работу без аппаратных показаний. Кнопка недоступна во время проверки или бенчмарка. Можно сразу запускать собранный `RAMChecker.exe` от администратора через контекстное меню Windows.

При обычном запуске проекта из Visual Studio или через `dotnet run` также доступна эта кнопка. Перезапуск создаёт отдельный процесс: отладчик к нему автоматически не подключается. Если нужна пошаговая отладка аппаратного мониторинга, откройте **Visual Studio от имени администратора**, загрузите решение и запустите проект через F5. Для Visual Studio Code аналогично запустите редактор от администратора перед запуском отладчика .NET. Windows передаёт повышенные права запускаемому процессу; настройки проекта не обходят UAC. [Документация Microsoft о правах отладчика](https://learn.microsoft.com/en-us/visualstudio/ide/user-permissions-and-visual-studio?view=visualstudio).

## Возможности первой версии

- Обзор и паспорт каждого модуля через WMI: производитель, модель, серийный номер, объём, тип, слот/банк, настроенная скорость и напряжение.
- Реальные показания физической памяти ОС, commit и системного кэша, график последних 60 измерений. Интервал: 1, 2 или 5 секунд.
- Быстрая проверка (10 минут), полная (2 часа) и циклическая до остановки. Завершается целый проход; длительность может немного превышать выбранную.
- Moving Inversions по опубликованной методике Memtest86+: заполнение, проверка с инверсией вперёд, проверка с инверсией назад. Быстрый профиль использует нули, единицы, шахматный и воспроизводимый псевдослучайный шаблоны; полный и циклический добавляют бегущую единицу. Проверка работает в фоне, поддерживает отмену и остановку по первой ошибке.
- Текущие первичные, вторичные, третичные и дополнительные тайминги контроллера Ryzen, MCLK/UCLK/FCLK, поддерживаемые измеренные напряжения и температура DDR4 TSOD через ZenStates-Core / PawnIO. Профили SPD не выдаются за текущие настройки. Показаны источник и время опроса; интервал общий с мониторингом (по умолчанию 1 с), пересекающиеся опросы не запускаются.
- Измерение read/write/copy в обзоре: два буфера по 64 МиБ, прогрев, медиана пяти измерений. Память выделяется до запуска таймера. Чтение — скалярный цикл C#, запись — `Array.Fill`, копирование — `Array.Copy`; вычисляется контрольная сумма и проверяется копия. Копирование считает размер полезных данных, не сумму чтения и записи на шине. Запуск диагностики и бенчмарка одновременно исключён. Результат отображается на экране до закрытия приложения; в историю проверок он не записывается.
- Ограничение выбранного объёма с резервом для ОС. Начальный объём — 512 МБ; минимальный — 64 МБ.
- История, журнал, счётчик несовпадений и первые 1000 записей с ожидаемым/прочитанным значением и смещением в буфере. Различаются завершение, ошибки, остановка, прерывание и сбой запуска.
- Промежуточное автосохранение каждые 10 секунд и сохранение после завершения, если включено. Следующий запуск распознаёт незавершённые сессии.
- HTML/CSV-экспорт, рекомендации по результату, методы теста и снимок конфигурации при запуске. «Печать / PDF» использует системный диалог печати; для PDF нужно выбрать Microsoft Print to PDF. Интерфейс — русский, светлая тема.

В интерфейсе четыре раздела: «Обзор», «Тестирование», «Результаты» и «Настройки». «Обзор» объединяет паспорт выбранной планки, тайминги и датчики, текущую загрузку, график и замер скорости. Планка выбирается в списке над её характеристиками. Карточка «Всего памяти» показывает объём физической памяти, который видит Windows после аппаратного резерва: например, 15,9 ГБ при двух установленных модулях по 8 ГБ. Объёмы самих модулей остаются паспортными.

«Результаты» — история диагностических запусков: дата, режим, проверенный объём, длительность, проходы, ошибки и рекомендации. Можно выбрать прежнюю проверку и выгрузить HTML/CSV или отправить её на печать/PDF. История и настройки хранятся в `%LOCALAPPDATA%/RAM Diagnostic Suite/`. Это внутренние JSON-файлы приложения; папку экспортируемого отчёта пользователь выбирает в диалоге сохранения. Путь к внутреннему хранилищу из настроек убран. Если файл истории повреждён, приложение сохраняет его без перезаписи и показывает сообщение. Результаты текущего запуска при этом доступны в интерфейсе для экспорта.

## Границы диагностики

Тестируется обычная память процесса, которую Windows может выгружать. Это не загрузочная проверка всей физической RAM, не диагностика конкретной планки и не подтверждение совместимости или равной эффективности с Memtest86+. Использована методика алгоритма, а не код Memtest86+. Кэши не отключаются, физические страницы не закрепляются. Нагрузочный режим всех ядер, Modulo-20, bit fade и Rowhammer пока не реализованы. Бенчмарк оценивает скорость конкретных операций программы, зависит от CPU/кэша/фоновой нагрузки и не измеряет предельную пропускную способность DRAM. Latency и сравнение с эталонами не добавлены.

Для аппаратного мониторинга нужны поддерживаемый Ryzen, установленный [PawnIO](https://pawnio.eu/) и запуск приложения **от администратора**. Повышение прав запрашивается только кнопкой через UAC. Приложение само не устанавливает драйверы и не меняет частоты/напряжения. WMI, статистика ОС и проверка буфера работают без этих условий. Поддержка таймингов Intel не реализована. Доступность датчиков зависит от платы и модулей; отсутствие температуры не доказывает отсутствие физического датчика. Напряжение SoC относится к контроллеру, VDIMM — к памяти. Частота SMU — телеметрия, а не вычисление из паспорта WMI. Источник отдельного показания виден во всплывающей подсказке строки; подробная конфигурация сохраняется в отчёте.

Скорость и напряжение в паспорте модуля получаются через WMI и показывают настроенную конфигурацию Windows; это объясняется во всплывающих подсказках. Текущие аппаратные показания находятся в блоке «Тайминги и датчики». Кэш и доступная память могут пересекаться; складывать их нельзя. История хранит снимок при запуске, а не непрерывный журнал всех аппаратных измерений.

Критерии из исходного ТЗ (99% обнаружения ошибок, 95% совместимости, 24 часа непрерывной работы, Linux/ARM64 и лимит памяти приложения 50 МБ) не подтверждены и не заявляются. Буфер проверки занимает выбранный пользователем объём сверх памяти интерфейса.

## Сборка и устройство проекта

```powershell
dotnet build RAMChecker/RAMChecker.slnx -c Release
```

В решении один проект с обычными конфигурациями Debug и Release. Отдельные скрипты и конфигурация самопроверок удалены. Для запуска и сборки Python не нужен.

Оформление использует стандартные элементы WPF без собственных шаблонов кнопок и списков. Сценарии приложения сохранены. В XAML каждый вложенный элемент расположен на отдельной строке; отступ — четыре пробела. Общие правила находятся в `.editorconfig`. Количество строк после раскрытия разметки не отражает увеличение логики приложения.

Диагностика, бенчмарк, мониторинг Windows, аппаратные датчики, хранение и экспорт находятся в отдельных сервисах. `MainViewModel` связывает их с экраном и напрямую реализует `INotifyPropertyChanged`. `Komanda` — небольшой адаптер кнопок к `ICommand`; дополнительных MVVM-фреймворков нет.

После чистки и объединения разделов 30.10.2026 Debug/Release собраны без предупреждений. Во временной среде вне проекта проверены оба профиля диагностики, внесение ошибок в буфер, отмена, резерв памяти, хранение и отчёты. Все четыре представления WPF проверены при 1440×960 и 1080×720, в том числе с таблицей аппаратных показаний; предупреждений и ошибок привязок нет. В реальном окне проверены отображение 15,9 ГБ, переключение планок, запуск/остановка проверки 64 МБ и переход к сохранённому результату (5 секунд, 9 полных проходов, 0 ошибок). Бенчмарк проверен при предшествующей чистке; его логика не менялась. Независимый обзор исходников не выявил проблем; шаблоны тестирования, результатов и графика совпадают с версией до объединения. Аппаратный опрос от администратора и фактическая печать PDF повторно не проверялись.

## Исследование аналогов

См. [отчёт](docs/reference-analysis.md): REA, локальные TestMem5, CPU-Z MSI и OCCT, наблюдения, SHA-256 и границы анализа. Код и DLL этих трёх программ не включены. Для аппаратных параметров добавлена открытая ZenStates-Core: закреплённая версия, исходники, лицензия и инструкция пересборки находятся в [vendor/README.md](vendor/README.md).

## Как читать код перед защитой

Последовательность: `App.xaml` открывает `MainWindow` → окно вызывает `MainViewModel.InitializeAsync()` → WMI загружает модули, таймер обновляет мониторинг → команда запуска вызывает `StartAsync()` → сервис проверяет буфер → результат сохраняется и показывается в истории.

| Где | Что объяснять |
|---|---|
| `MainWindow.xaml` | Разметка четырёх разделов, общие стили и привязки к свойствам |
| `MainWindow.xaml.cs` | Открытие/закрытие окна, диалоги сохранения и печати |
| `ViewModels/MainViewModel.cs` | Состояние экрана и порядок действий пользователя |
| `Models/` | Поля модуля, результата проверки и настроек |
| `Services/WMIServiceMemory.cs`, `MemoryMonitor.cs` | Паспорт модулей и текущая статистика Windows |
| `Services/HardwareMemoryMonitor.cs` | Чтение готовой библиотеки: тайминги, частоты, датчики; обработка недоступности |
| `Services/MemoryDiagnosticService.cs` | Запись шаблонов, сравнение, отмена и ошибки |
| `Services/MemoryBenchmark.cs` | Прогрев, замер read/write/copy, медиана и проверка данных |
| `Services/LocalStorage.cs`, `ReportExporter.cs` | Сохранение JSON и формирование отчётов |
| `Helpers/Komanda.cs` | Команда кнопки WPF (`ICommand`) |

Диагностика буфера, бенчмарк, работа с Win32 API, хранение и отчёты реализованы в проекте. Аппаратные тайминги и датчики получает готовая сторонняя ZenStates-Core; её исходники и лицензия явно указаны в `vendor`. Переписывание этой библиотеки в текущую чистку не входит.
