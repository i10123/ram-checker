# MemScope

Приложение для диагностики оперативной памяти на C# / WPF (.NET 10, архитектура MVVM).

## Возможности

- **Обзор.** Производитель, модель, серийный номер, тип, объём, слот, напряжение и текущая частота каждого модуля (WMI). При запуске от администратора — номинальная частота, тайминги CL-tRCD-tRP-tRAS, tRC и температура модуля из микросхемы SPD. Загрузка памяти в реальном времени с графиком, приблизительный однопоточный замер скорости чтения, записи и копирования, задержка памяти.
- **Тестирование.** Быстрый (10 минут), полный (2 часа), циклический и стресс-режим (вся свободная память до остановки). Собственный алгоритм «Свой адрес с инверсией» работает на всех ядрах. Карта буфера проверки показывает ход прохода по каждой 1/256 части буфера. Перед большой нагрузкой программа предупреждает пользователя, проверку можно остановить при обнаружении ошибки: блоки проверяются параллельно, поэтому другие потоки могут успеть зафиксировать ещё по одной ошибке. Во время проверки Windows не уходит в спящий режим. Ход проверки виден на значке в панели задач (при ошибках полоса красная). По завершении звучит системный сигнал, а итог появляется цветной плашкой на странице.
- **Результаты.** История проверок сохраняется автоматически, а во время проверки раз в 10 секунд сохраняются счётчик, карта и список ошибок, поэтому после аварийного закрытия результат не теряется. Историю можно удалять. Список найденных ошибок (первые 1000) и HTML-отчёт с картой буфера и объёмом, который действительно прошёл полный проход.

## Алгоритм проверки

Буфер выделяется вне сборщика мусора и сразу возвращается Windows после проверки. Каждый проход состоит из трёх шагов по всему буферу:

1. **Заполнение.** В каждую ячейку записывается значение шаблона. Четыре шаблона сменяют друг друга по проходам:
   - **свой адрес:** `адрес × 0x9E3779B1 + проход × 0x7F4A7C15`;
   - **шахматный:** `0xAAAAAAAA` и `0x55555555` через ячейку, каждые четыре прохода они меняются местами;
   - **бегущая единица:** `1 << ((адрес + проход) mod 32)`, то есть в слове один единичный бит, а у соседней ячейки он сдвинут на разряд;
   - **случайный:** значение адресного шаблона, перемешанное сдвигами xorshift (`x ^= x << 13; x ^= x >> 17; x ^= x << 5`).
2. **Проверка вперёд.** Ячейки читаются по возрастанию адреса и сравниваются с ожидаемым значением, затем в каждую записывается инверсия.
3. **Проверка назад.** Ячейки читаются по убыванию адреса, сверяется инверсия, затем возвращается исходное значение.

Шаблон адреса находит ошибки адресации, шахматный — влияние соседних ячеек друг на друга (у соседей все биты противоположные). Бегущая единица находит замыкание соседних линий данных внутри слова, а после инверсии на шаге 2 становится бегущим нулём. Случайный шаблон находит ошибки, которые проявляются только на определённых данных. Шаги 2 и 3 находят «залипшие» биты. Идея прямого и обратного обхода с инверсией взята из алгоритма Moving Inversions, случайный шаблон — из теста Random (оба есть в Memtest86+).

### Имитация ошибки

Чтобы увидеть, как программа показывает неисправную память, запустите её с ключом `--imitaciya`:

```powershell
dotnet run --project RAMChecker/RAMChecker.csproj -c Release -- --imitaciya
```

После заполнения в блоке 86 карты переворачивается бит 5 одной ячейки. Прямой обход находит его в каждом проходе: клетка краснеет, ошибка попадает в журнал, результаты и отчёт.

## Чтение SPD

Тайминги читаются напрямую из микросхемы SPD планки DDR4 по шине SMBus через драйвер [PawnIO](https://pawnio.eu/). В программу встроены подписанные модули драйвера `SmbusPIIX4.bin` (AMD) и `SmbusI801.bin` (Intel). Расшифровка байтов SPD, проверка контрольной суммы и перевод времени в такты выполнены в `Services/SpdReader.cs` по стандарту JEDEC.

Для этих данных нужны установленный PawnIO и запуск от администратора (кнопка на странице «Обзор»). Остальные функции работают без прав администратора.

Паспорт SPD и сведения WMI не содержат общего признака планки (модель и серийный номер лежат во второй странице SPD, которую программа не читает). Поэтому данные сопоставляются по порядку слотов и только если число модулей и объём каждого совпадают, иначе программа сообщает, что паспорт нельзя отнести к слотам, и тайминги не показывает. Паспорт с недопустимыми значениями (например, нулевым периодом такта) отклоняется, даже если контрольная сумма верна.

## Ограничения

- Проверяется только буфер, выделенный программой. Часть памяти занята Windows и другими программами, поэтому отсутствие ошибок не доказывает исправность всей установленной памяти.
- Карта и смещения ошибок относятся к буферу программы, а не к физическим адресам: по ним нельзя определить неисправную планку. Для этого проверяйте планки по одной.
- Программа оставляет Windows резерв свободной памяти, но не закрепляет буфер в RAM, поэтому часть страниц всё же может уйти в файл подкачки.
- Замер скорости приблизительный: один поток, буферы по 256 МБ (вдвое больше кэша L3 настольных процессоров, но не всех серверных). Результат зависит от частоты процессора и фоновой нагрузки.

## Запуск

Нужны Windows 10/11 и .NET 10 SDK.

```powershell
dotnet run --project RAMChecker/RAMChecker.csproj -c Release
```

## Самопроверки

Проект `RAMChecker.Tests` — консольная программа без тестового фреймворка: проверяет алгоритм, отмену и остановку на ошибке, неверные параметры, расшифровку SPD, отчёт и чтение истории. Драйвер и права администратора не нужны, проверка идёт около 10 секунд и занимает до 1 ГБ памяти.

```powershell
dotnet run --project RAMChecker.Tests -c Release
```

Код возврата — число непройденных проверок. Чтение SPD на реальном оборудовании проверяется вручную (нужны PawnIO и права администратора), результат записывается в файл:

```powershell
dotnet run --project RAMChecker.Tests -c Release -- spd spd.txt
```

## Устройство проекта

| Папка | Содержимое |
|---|---|
| `Views/` | Разметка трёх страниц |
| `ViewModels/` | `MainViewModel` — навигация и история; `ObzorViewModel` и `TestirovanieViewModel` — страницы «Обзор» и «Тестирование» |
| `Models/` | Модуль памяти и результат проверки |
| `Services/` | WMI, SPD и драйвер PawnIO, алгоритм проверки, замер скорости, мониторинг, хранение и отчёты |
| `Helpers/` | `Komanda` (команда кнопки) и `NabludaemyObject` (базовый класс ViewModel) |
| `RAMChecker.Tests/` | Самопроверки (рядом с папкой `RAMChecker/`) |

История хранится в `%LOCALAPPDATA%/MemScope/`. Логотип нарисован в `Assets/Logo.xaml`, иконка `logo.ico` собрана из него.
